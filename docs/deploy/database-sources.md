# 数据库表数据源

在“数据中心”点击“连接数据库”，选择 MySQL 或 PostgreSQL，填写主机、端口、数据库名称、账号和密码，点击“连接并获取表”。连接成功后选择一张表，填写数据源名称并创建。新数据源可直接在图表数据面板中选择；每次请求读取数据库当前数据，而非首次连接时的快照。

数据库地址从 BI 后端所在机器解析和连接，填写主机名或 IP，不包含 `mysql://`、`postgresql://` 或 URL 路径。支持自定义端口；勾选 TLS 时验证服务器证书。请为 BI 使用只读数据库账号。服务端也以只读事务执行查询，不提供任意 SQL 输入。

创建的数据源仅所属登录用户可见。删除操作只删除 BI 连接记录，不删除远程表。数据库表数据源目前直接用于图表，不提供文件数据集的加工草稿功能。

## 更新部署

本次新增 `DatabaseDatasetRecord` 表。Windows 仍按原部署流程执行 `prisma/migrate-postgresql.ps1`，它会自动执行新增 SQL 迁移；开发环境使用 `pnpm prisma:migrate:deploy`。无需新增 npm 依赖，使用项目现有的 mysql2 和 pg 驱动。

## 凭据存储

连接信息（包括密码）使用 AES-256-GCM 加密后保存在应用数据库，接口不返回连接密码，浏览器不将它写入本地存储。

可设置 `DATABASE_CONNECTION_KEY` 为 Base64 编码的 32 字节随机密钥。没有配置时，系统首次保存数据源会在应用根目录生成 `.runtime/database-connection.key`，并在后续启动时复用。该文件已加入 Git 忽略规则。

Windows 文件位于 `C:\zhbi\.runtime\database-connection.key`，不在 `apps` 的镜像更新范围内。部署更新时保留它；迁移主机或恢复应用数据库时，必须同时保留同一密钥，否则已有连接无法解密。该文件和 `.env` 一样不得加入制品或提交代码仓库。设置或更换环境变量密钥前，应确认现有连接使用的密钥，不能直接替换。

## 查询范围

- 连接超时约 10 秒，查询设置执行时长限制。
- 最多列出 2000 张可访问表，每张表最多 256 个字段。
- 筛选、日期范围和图表聚合在源数据库执行；聚合计算基于满足筛选条件的全表。
- 每次最多返回 5000 行；超过时返回明确的截断提示，可通过筛选或聚合缩小结果。
- bigint 等大整数按文本字段处理；常规整数、小数按数值字段处理；二进制按 Base64 文本处理。
